# FN-2.0 分发与反馈契约

**目标版本：FN-2.0；尚未实现。** 本版替换旧的固定普通订阅契约，旧接口和旧状态无需兼容。collector 与 Android 只通过本文件规定的版本化网络契约共享数据，不共享数据库或内部实现。

## 候选清单请求与响应

客户端发起匿名请求，服务端返回契约版本、清单版本/生成与到期时间、可核对的内容摘要、有限数量的候选配置，以及每条候选对应的服务端匿名标识。服务端按近期质量、分配压力和来源多样性组合清单；请求可带一次性的匿名选择值以避免所有客户端得到相同清单，不要求账户、持久设备 ID、位置或客户端探测历史。清单可以在次数与流量预算内重取。服务端保存节点级聚合分配计数，不保存长期的用户—节点关系。候选配置必须经 HTTPS 传输；其敏感字段不得进入日志、分析或错误响应。

服务端可明确标记安全撤销的候选；普通清单缺席不等于撤销。客户端按本机指纹合并旧有效节点与新清单，安全撤销立即移除。清单为空、超时或发布失败时不得把最后有效清单替换为空。版本、摘要和候选标识必须在同一次原子发布中一致。策略组与最终选择仅由客户端管理。

清单只能包含已通过完整安全与功能检查的节点；待测节点不得下发。

## 反馈

功能启用后匿名反馈默认开启，设置中可单独关闭。客户端先确认普通网络正常，再按批次发送服务端匿名候选标识、粗粒度成功/失败类别、延迟档位和时间窗。不得发送完整配置、凭据、UUID、私钥、客户端 IP、设备 ID、浏览数据或测试载荷。服务端不保存请求 IP；入口限流、聚合报告、短期删除原始报告。单个用户或一次失败只能触发降权或复测，不能触发全局删除。关闭反馈不影响清单获取与本地选路。

## 失败语义

版本不匹配、摘要不匹配或清单不完整时客户端拒绝应用并保留本机旧有效节点；服务端保留最后有效发布。反馈端点失败不得影响清单和连接。字段、状态和保留期限的具体编码在实现前写成无秘密夹具，并同时更新本文档。

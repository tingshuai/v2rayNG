# Android 状态与选择设计

## 复用现有能力

客户端应扩展既有订阅更新、真实延迟测试、MMKV 持久化和 Xray policy group / observatory / balancer 能力。不要创建平行的无生命周期后台调度器或替代核心的切换实现。

## 本地状态

每个候选按秘密安全指纹而非订阅 GUID 关联历史。最小状态包括：最近成功/失败时间、滚动成功率、连续失败数、EWMA 延迟、EWMA 抖动、隔离截止时间和最后选中时间。

订阅更新是多记录写入：新候选、历史重关联和过期记录清理必须作为可恢复的整体完成。升级旧状态时必须保留向后兼容迁移和回归测试。

## 测试与评分

仅在生命周期受控的后台任务中测试有限集合。优先选择：已验证且近期健康的候选、小量未探索候选、隔离到期候选。网络受限、移动网络或电量条件不满足时应延后或缩小测试，而不是全量探测。

排名先比较近期真实成功、成功率和稳定性，再比较延迟和抖动。服务端分数只能帮助首次抽样，不能推翻客户端测得的健康状态。

## 选择、切换与隔离

专用免费节点策略组负责运行期分流和可用性观测。选中的健康节点不会因单次失败或一次较高延迟被替换：必须达到连续失败门槛，或挑战者在重复测量中持续显著更优，才允许切换。失败节点按 TTL 隔离；隔离期后以小样本方式重新测试。

这避免了自动模式在不稳定公共节点之间反复跳转。任何“更新后自动测速并删除单次失败节点”的既有设置都不能直接作为本功能的失败判定规则。

# 数据保留与威胁模型

## 核心事实

免费节点由未知运营者控制。即使 HTTPS 能保护部分网页内容，也不应通过它们发送账号、密码、支付信息、企业数据或其他敏感流量。客户端启用前必须明确展示这一风险。

## 威胁与控制

| 风险 | 控制 |
| --- | --- |
| 恶意或被接管的公开节点 | 默认关闭、明确警示、仅作候选、本地真实验证和失败隔离。 |
| SSRF、内网访问或 DNS 重绑定 | 服务端在 DNS 后和连接前校验公网地址；拒绝私有与保留地址。 |
| 第三方测试结论不适用于用户网络 | 本地真实探测是唯一的最终选择依据。 |
| 频繁探测耗电或耗流量 | 有界候选集、网络/电量约束、短超时和小样本探索。 |
| 订阅替换导致历史错配 | 以连接相关字段生成秘密安全指纹，不使用 GUID、备注或列表位置。 |
| 日志泄漏凭据或用户隐私 | 不记录完整链接、认证材料、私钥、用户 IP、测试载荷或浏览数据。 |

## 数据保留

客户端默认仅本地保留匿名指纹、最近探测结果、聚合成功/失败计数、延迟/抖动统计、隔离到期时间和必要的迁移版本。服务端只保留运行所需的来源健康摘要和不含秘密的聚合检查指标。

任何新增数据项都必须在实现前写明：用途、存储位置、保留期、删除触发条件、是否离开设备，以及为何不能用更少的数据完成同一目的。

# FN-2.0 Android 状态与选择

**FN-2.0 实施状态：已实现并完成基础真机验收。** 客户端使用 MMKV、受生命周期约束的后台任务、真实探测和 Xray 策略组能力。免费节点功能由用户主动开启；未开启时原有 VPN、仅代理、root 和订阅行为不变。Android 10 专用测试机已从生产 manifest 导入候选并验证后台反馈；连接自动策略组时没有本机成功候选，客户端现在会明确报错并清理失败启动资源，不再生成引用缺失 `balancer-main` 的配置。用户授权对专用机进行真实节点连接验证；截至本次验收，没有节点通过本机验证。

免费节点订阅更新读取 `/manifest`，校验版本、时效、摘要、候选 ID 和配置，再通过现有 profile parser 导入。客户端按连接字段设备本地 HMAC 指纹保存服务端候选 ID 映射；替换前，将最近 7 天内测通、未隔离且未撤销的最多 16 条缺席旧配置并回新订阅。Xray 专用策略组只纳入至少一次本机测通、未隔离且未撤销的 profile；未测新候选与隔离候选通过现有有限 `RealPingWorkerService` 后台抽样探索。该合并使用现有批量 profile 保存操作。服务端撤销项会从策略组和专用订阅的本地 profile 存储中物理删除，并清除对应历史与映射。本地失败历史仅在关闭功能时清除。若自动策略组没有可用成员，启动前返回本地化错误，不创建缺少 balancer 的路由配置。

## 首页与列表交互（FN-2.1 设计）

首页中间区域改为订阅列表，沿用现有 `MainTopBar` 的菜单、标题、搜索、导入加号和更多菜单，以及现有底部连接栏和悬浮启停按钮的外观与操作。免费节点订阅默认排在首位且不能被用户删除；用户添加的订阅可编辑、删除和手动更新。普通订阅仍沿用现有每订阅自动更新设置，以及订阅偏好中的更新后自动测速选项，不新增后台调度能力。

每个订阅卡片按 GUID 加载节点统计，展示总数、真实测试正常数、失败数和未测试数，并标出最近真实测试时间。未测试不得算作正常。点击订阅卡片进入其节点列表；顶部工具栏保持原样。节点行展示协议、可识别的国家/地区、真实延迟和连通性。地区优先取 feed 元数据，缺失时再进行安全的地区识别；无法确认时显示“未知地区”，不得根据名称猜测。国家筛选只对识别成功的地区生效。

底部现有信息区域继续响应“测试当前节点”操作，显示连接目标名称和最近延迟；未连接时悬浮按钮启动所选节点或当前订阅的自动策略，运行时悬浮按钮停止服务。免费节点默认使用专用自动策略组，普通订阅与手动导入节点仍可通过现有选择机制连接。订阅列表和节点列表共用当前启停按钮，不另建连接按钮或并行连接流程。

后台仅测有限候选：近期健康、未测新节点、隔离到期的少量探索样本。当前实现每批最多测 8 条（4 条健康、2 条新候选、2 条隔离恢复），要求有网络且电量不低。连续 3 次失败后隔离 30 分钟；最近 7 天内测通且缺席的配置最多保留 16 条。当前节点保持由现有 Xray 策略组/balancer 管理；本机评分在挑战者连续两轮领先 800 分后更新本地优选记录。服务端撤销候选会立即从策略组排除，并从专用订阅的本地 profile 存储中物理删除；对应的历史记录、候选映射和本地优选记录也会清除。服务端 manifest、质量权重与撤销已接入。完整代理链路未在真机上使用未信任候选验证。

匿名质量反馈使用现有有限探测任务与独立的可关闭设置。报告仅在普通非 VPN 网络确认可用后发送；启用前继续展示免费节点不适合凭据、支付等敏感流量的警示。

测试必须覆盖清单更新时旧好节点保留、失败节点退出、冷却后恢复、安全撤销、当前节点稳定、后台取消/约束、反馈开关和网络健康前置条件，以及 VPN、仅代理和 root 受影响路径。

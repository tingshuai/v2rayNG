# FN-2.0 采集与分发运行手册

**目标设计，尚未部署。** 现有容器和定时器仍执行旧代码；本文件定义后续直接替换的运行语义。collector 独立于 Android 构建和部署。来源只能是显式登记、公开且无需认证的 HTTPS 订阅；不抓取登录态、Cookie、验证码或令牌来源。

## 来源获取

来源注册表记录稳定 ID、地址、启用状态、独立最短获取间隔、最后成功/失败和暂停原因。成功获取才更新来源与候选的关联；失败不把旧节点判为消失。连续三次抓取或解析失败暂停来源，显式启用才恢复。单个来源无合格节点、候选全部筛掉或批次超时只记健康信号，不自动暂停。来源变更审计不含秘密。

## 候选池和筛选

解析、规范化后用服务端密钥 HMAC 指纹跨来源去重。数据库记录状态、来源关联、最近出现、检查结果、下次复测和过期条件；不记录完整代理配置。先做格式、公共地址和重复项检查，再从全局队列轮转选取候选做 TCP 与小型代理 HTTP 204 检查。每来源有基本份额，未测、到期健康和隔离到期候选分别有预算；跨来源相同指纹只占一次。每次 DNS 解析后及连接前均校验公网地址，防止 SSRF 和 DNS 重绑定。禁止端口扫描和带宽测试。

格式/地址安全违规立即停发。普通失败先降级，经多轮失败隔离和复测；长期失败才删除配置并暂留不可逆失败记录。来源消失需所有关联来源成功更新后持续缺席、再达到保留期才过期。近期可信成功反馈可延后普通失效删除。具体阈值在实现前用 VPS 的负载和来源节奏定值并写入本手册；不得沿用旧的固定“每来源抽 50 条”规则。

## 分发和故障

按近期成功、稳定性、新鲜度、分配压力与保守容量上限加权组合清单，约束来源多样性和新节点探索份额。只记录每节点聚合分配计数，不保留长期用户—节点映射。版本、内容摘要、匿名候选标识和安全撤销信息须一致发布。空结果或发布失败维持最后有效清单及回退副本。定时器不得并行运行同一采集批次；健康检查要验证发布新鲜度和清单可读取。

反馈默认随功能开启，可单独关闭。仅接收通过网络健康前置检查的粗粒度报告；入口限流并汇总，单次报告不全局删除。日志只含组件、来源 ID、匿名状态与聚合计数；不得记录代理 URL、凭据、UUID、私钥、客户端 IP 或测试载荷。

## 部署与验证

在测试环境备份数据库和最后有效发布，直接替换旧 collector 与契约，不做双轨运行或旧状态迁移。异常时恢复工件并修复 FN-2.0。实现后验证不同来源周期、来源失败、长列表轮转、跨来源去重、失败冷却、删除复测、分配集中度、反馈误报、空发布及恢复；定期清理过期数据并检查磁盘/CPU/内存和发布新鲜度。

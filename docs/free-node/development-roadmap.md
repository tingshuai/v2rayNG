# FN-2.0 开发节奏与验收

**目标版本：FN-2.0；尚未实现。** 本路线直接替换测试阶段的旧机制。2026-11-11 的 P0–P4 记录保存在 [历史试运行记录](p4-end-to-end-trial.md)，不表示 FN-2.0 已通过验收。免费节点功能由用户主动启用；启用后的匿名质量反馈默认开启，可单独关闭。未启用用户维持原有 v2rayNG 行为。

1. **契约和数据规则**：固定来源周期、跨来源指纹、候选状态、过期/删除、分发、反馈以及保留期。交付无秘密夹具和数据库迁移设计。验收：每项数据有用途、位置和删除规则。
2. **VPS 候选池**：不同来源按各自周期成功更新；跨来源去重；来源失败不删旧节点；轮转探测使长期未测节点获得机会；失败冷却与到期复测。验收：不同周期、不同来源、长列表和重复失败的确定性测试通过。
3. **质量分发**：依据近期成功、稳定性、新鲜度和分配压力按权重组合清单，约束来源多样性，给新节点有限份额。清单失败可有限换取；空批次保留最后有效发布。验收：不同请求的清单有差异，可靠节点可用，集中度受控，发布可回退。
4. **Android 本地池与选择**：新清单与本机近期有效旧节点合并；反复失败退出本机可选集合；健康当前节点保持，连续失效或持续明显更好的挑战者才触发切换。验收：跨更新保留、失败清理、网络/电量约束及 VPN、仅代理、root 受影响路径检查通过。
5. **默认反馈**：功能启用后反馈默认开启，可单独关闭。先确认普通网络正常，仅上传匿名候选标识及粗粒度结果；单次失败不全局删除。验收：关闭反馈不影响功能、没有秘密或设备标识泄漏、误报和滥用有界。
6. **测试环境直接替换**：用 FN-2.0 替换旧 collector 与 Android 免费节点逻辑，不做新旧机制并行或旧数据兼容。切换前备份可恢复的测试数据与最后有效发布，失败时恢复工件并修复 FN-2.0。

必须记录每天探测的不同节点数、重复探测率、来源覆盖、用户找到可用节点的比例与时间、分配集中度及资源消耗。Android 和 collector 各自独立构建、测试和运行；文档、契约和测试夹具随实现更新。

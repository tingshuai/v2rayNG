# 免费节点功能：开发节奏与验收

## 目标和边界

目标是交付默认关闭、用户明确同意后可启用的免费节点候选订阅与稳定自动选择能力。采集服务独立运行；Android 客户端只使用标准订阅和本地测量结果。每一阶段结束时，上一阶段产物必须可独立运行、回退和验证。

不在本项目中保存 VPS 凭据、生产地址、来源账户 Cookie、完整节点转储或用户网络数据。

## 总体顺序

```
P0 设计冻结 ──> P1 采集服务 MVP ──> P2 客户端安全接入
                                           │
                                           v
P3 本地评分与稳定选择 ──> P4 端到端试运行 ──> P5 小范围发布与运营
```

P1 可与 P2 并行准备，但 P2 的真实接入测试依赖 P1 提供稳定的非生产测试订阅。P3 依赖 P2 的订阅归属和本地状态模型。P4、P5 只在前序验收完成后开始。

## P0：设计冻结与测试夹具

**目的**：在写功能前固定安全边界、订阅兼容性和可测试输入。

**工作项**

- 确定第一批无需人工审核的来源准入标准和停用规则；来源内容不写入仓库。
- 确定来源注册表、候选记录、运行记录和审计记录的最小数据库字段及保留期。
- 确定首版单机技术栈：Go、SQLite（WAL）、Docker Compose、受限 sing-box 探测和 Cloudflare Tunnel；为升级 PostgreSQL/多实例列出触发条件。
- 固定普通订阅输出与可选元数据的版本规则；制作不含真实凭据的测试夹具。
- 为指纹、评分、滞回、失败隔离和迁移编写确定性测试用例清单。

**交付物**：经确认的契约、数据库迁移草案、测试夹具和威胁模型更新。当前冻结内容见 [P0 设计冻结](p0-design-freeze.md) 与 [P0 测试夹具](fixtures/README.md)。

**完成标准**：没有生产节点或秘密进入仓库；普通订阅不依赖私有元数据；每项持久化数据都有用途与删除规则。

## P1：独立采集服务 MVP

**目的**：可靠地产出一条可由既有 v2rayNG 订阅解析的候选订阅。

**工作项**

- 建立来源注册表与审计；新增、修改、暂停和删除来源均通过该入口。
- 实现拉取、解析、规范化、秘密安全去重、每来源限流及短超时。
- DNS 解析后与连接前两次校验公网地址，防止 SSRF 和 DNS 重绑定。
- 实现有界的语法、TCP/TLS 和小型 HTTP 204 初筛；保留最后一次成功输出。
- 发布只含候选代理的标准订阅，并提供健康状态与告警。

**交付物**：可部署服务、数据库迁移、无秘密配置样例、运维告警和测试环境订阅。

**完成标准**：异常来源可单独暂停；私网/环回目标被拒绝；失败不覆盖最后有效订阅；不进行端口扫描或带宽测试。

### P1 验收记录（2026-11-11）

**P1 验收通过。** 采集器确定性测试已通过；独立 VPS 实例已验证来源暂停/恢复、最后有效发布保留与 loopback 发布服务；部署侧数据库、日志和临时文件审计通过，且测试数据与密钥已清理。完整证据见 [P4 端到端试运行记录](p4-end-to-end-trial.md)。来源准入规则已统一为公开可访问、无需认证的技术条件，仍拒绝任何需要登录、Cookie、验证码、认证令牌或绕过访问控制的来源。

## P2：Android 安全接入

**目的**：用户能主动开启功能、导入专用候选订阅并理解风险，同时不影响既有用户。

**工作项**

- 增加功能开关和首次风险同意；所有可见文本进入全部支持语言资源。
- 创建并识别专用免费节点订阅归属，复用现有订阅更新机制和网络约束。
- 实现连接相关字段的秘密安全指纹及旧状态迁移基础。
- 创建由客户端管理的专用策略组；不接受外部订阅下发的策略组控制。
- 使关闭功能、删除订阅或订阅替换时能完整清理/恢复关联状态。

**交付物**：客户端设置与订阅接入、迁移逻辑、单元测试。

**完成标准**：默认关闭；不启用时原有订阅、选择和 VPN/代理/root 三条路径无变化；没有完整代理链接或用户数据进入日志。

### P2 验收记录（2026-11-10）

P2 已验收。Play Store Debug 的定向单元测试、全量 JVM 测试（126 项）与 APK 构建均已通过；模拟器已验证风险确认、启用后的专用订阅与策略组、重启后的状态保留、关闭清理及从订阅页删除后的清理。未启用状态下，VPN 与仅代理模式已验证不会创建免费节点订阅或策略组。

**保留的复测项（不阻塞 P2 验收）**：root 模式的真实服务运行检查尚未在测试环境执行。现有 userdebug 模拟器提供的 `su` 不兼容客户端使用的标准 `su -c` 入口，无法启用该模式；测试期间未改动客户端 root 实现。P4 端到端试运行前，须在具有 Magisk 或其他兼容 `su -c` 实现的隔离测试设备/模拟器上复测：功能保持关闭时启动和停止 root 模式，确认没有创建免费节点订阅、策略组或相关后台更新任务。

## P3：本地评分与稳定自动选择

**目的**：在用户自己的网络中，从有限候选中稳定选择，而非反复跳转。

**工作项**

- 基于现有真实延迟测试实现有界探测计划：健康节点、新节点、冷却结束节点三类小样本。
- 使用本地成功率、稳定性、EWMA 延迟/抖动建立确定性评分；服务端分数仅用于冷启动抽样。
- 实现连续失败阈值、挑战者重复优势、隔离 TTL 与恢复抽样。
- 将结果接入专用策略组及 Xray observatory/balancer；保留健康节点优先。
- 支持任务取消、网络/电量约束和新任务替换旧任务。

**交付物**：评分状态、选择器、后台执行边界和单元测试。

**完成标准**：单次失败不切换；单次更低延迟不抢占；稳定节点在阈值前保持；状态以指纹跨订阅替换关联。

### P3 实现记录（2026-11-10）

P3 已实现有界的本地探测计划、设备本地评分/隔离/滞回状态，以及在订阅替换后触发的 WorkManager 后台执行边界。探测复用现有真实延迟测量，并把专用 policy group 的运行期健康过滤保留给既有 Xray observatory/balancer；P3 不会改写用户当前服务器选择。确定性单元测试覆盖单次失败、挑战者重复优势、隔离与恢复抽样、探测上限和跨订阅历史迁移。2026-11-10 已在模拟器验证启用后 WorkManager 的受限任务启动、订阅更新替换旧任务和关闭后的任务取消；完整 JVM 套件仍受既有 `RootProcessRunnerTest` 的 4 个 Windows 进程启动失败阻塞。

### P3 验收记录（2026-11-11）

**P3 验收通过。** 已运行 Android 免费节点定向单元测试、完整 Play Store Debug JVM 测试与 Kotlin 编译；后两项均通过。P4 的真机 Wi-Fi 检查确认受限 `free-node-probe` 任务可完成，关闭功能后任务被取消；VPN、仅代理与 root 关闭态均不创建免费节点任务。计费网络检查作为 P4 的已批准验收例外保留为 P5 前补充复测，不改变 P3 的本地评分、隔离和滞回确定性验收结论。

## P4：端到端试运行

**目的**：验证服务端候选与客户端本地判断之间的完整链路。

**工作项**

- 使用隔离的测试来源和测试订阅验证更新、替换、失效、恢复和停用来源。
- 在 Wi-Fi 与移动网络条件下检查有界探测、隔离 TTL、切换滞回和耗电/流量边界。
- 覆盖 VPN、代理模式和 root 模式中受影响的路径；验证用户关闭功能后的恢复。
- 审计日志与数据库，确认无秘密、完整节点链接或用户网络数据泄漏。

**完成标准**：全部确定性单元测试通过；Android 所需 Gradle 检查通过；涉及后台、核心或 VPN 的行为经模拟器或真机检查。未运行的检查必须逐项列出命令和原因。

### P4 验收记录（2026-11-11）

采集器回归、Android 免费节点定向回归、公开发布链路只读基线、真机 Wi-Fi/关闭态路径，及隔离 VPS 实例中的来源生命周期和部署侧隐私审计，均已记录在 [P4 端到端试运行记录](p4-end-to-end-trial.md)。VPS 测试未修改生产 collector、容器或数据卷，并在完成后清理了测试容器、数据和运行时密钥。

**Not run（用户确认延期；验收例外已批准）**：计费网络下的有界探测、网络/低电量延后、隔离 TTL 与切换滞回尚未执行，因为本轮真机没有可用蜂窝数据服务。产品负责人已于 2026-11-11 批准该延期作为 P4 验收例外。因此 **P4 已验收通过**；此项保留为 P5 前的补充复测。

## P5：小范围发布与持续运营

**目的**：在可回退前提下逐步开放并保持来源与文档有效。

**工作项**

- 先向有限测试人群开启，观察来源健康、订阅更新失败率、客户端匿名聚合健康指标（如以后明确获得用户同意）。
- 为来源故障、误收录、订阅异常和客户端回退准备开关与操作手册。
- 定期复审来源准入、保留期、探测预算和用户风险提示。
- 每次上游同步、契约变更或运维调整时同步更新本目录。

**完成标准**：可在不发 Android 新版本的情况下停用单个来源或关闭服务端输出；回退过程不遗失用户已有普通订阅。

## 每个实现变更的固定检查

- 变更前确认其所属阶段和依赖是否已验收。
- 变更中更新本文档、受影响的设计文档与测试夹具。
- Kotlin/Java 生产代码至少运行对应测试类、`:app:testPlaystoreDebugUnitTest` 和 `:app:compilePlaystoreDebugKotlin`。
- 资源、Manifest、Gradle 或原生打包变更运行 `:app:assemblePlaystoreDebug`；按发行差异补充 F-Droid 检查。
- 涉及 Android 服务生命周期、VPN、核心、权限、后台或状态恢复时，补充模拟器或实体设备验证。

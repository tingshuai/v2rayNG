# FN-2.0 采集与分发运行手册

**FN-2.0 实施状态：部分实现，尚未部署。** 现有容器和定时器仍执行旧代码。collector 独立于 Android 构建和部署。来源只能是显式登记、公开且无需认证的 HTTPS 订阅；不抓取登录态、Cookie、验证码或令牌来源。

## 来源获取

来源注册表记录稳定 ID、地址、启用状态、独立最短获取间隔、最后成功/失败和暂停原因。成功获取才更新来源与候选的关联；失败不把旧节点判为消失。连续三次抓取或解析失败暂停来源，显式启用才恢复。单个来源无合格节点、候选全部筛掉或批次超时只记健康信号，不自动暂停。来源变更审计不含秘密。

## 候选池和筛选

当前实现对每个到期来源重新获取并解析其候选文本，服务端 HMAC 指纹用于单批跨来源去重；SQLite 不保存完整代理配置。SQLite 以来源 ID 持久化筛选游标，长列表每批从上次位置继续轮转；每批总探测上限为 50，预算在当批来源间平均分配，余数按日轮转。TCP/代理并发上限为 2。来源并发上限为 4，默认筛选时限为 30 秒，每个候选最多使用 3 秒 TCP/代理检查预算。先做格式、公共地址与去重检查，再做 TCP 和小型代理 HTTP 204 检查。每次 DNS 解析后及连接前均校验公网地址，防止 SSRF 和 DNS 重绑定。禁止端口扫描和带宽测试。

筛选游标、批次轮转、探测总量与并发边界已实现。SQLite 保存每指纹的成功/失败探测计数、最近探测、连续失败和隔离期限；健康候选 6 小时后复测，失败候选 30 分钟后复测，连续 3 次失败隔离 30 分钟。成功获取来源时写入候选关联；候选超过 30 天且所有关联来源的后续成功清单都确认缺席后才过期。细化状态冷却及基于可信反馈的延期删除仍未实现。50 个探测预算、2 个并发和 30 秒批次时限是保守首发上限，部署前仍须按 VPS 资源监测调整。

## 分发和故障

`/subscription` 仍返回标准 Base64 订阅，供现有 Android 订阅更新器读取。每次请求从最后有效发布中加权抽取最多 32 条；权重使用真实探测成功率、最近成功新鲜度、连续失败、候选来源重复惩罚与聚合分配计数，未测候选保留 0.20 的弱探索权重。只写节点级聚合分配次数。空结果或发布失败保留最后有效清单及回退副本。来源多样性硬约束、服务端容量上限和带摘要/撤销信息的版本化 manifest 尚未实现。定时器不得并行运行同一采集批次；健康检查要验证发布新鲜度和清单可读取。

匿名反馈端点、入口限流、聚合和客户端开关尚未实现；当前不得发送或记录候选质量反馈。实现后仅接收经普通网络健康前置检查的粗粒度报告，单次报告不得全局删除节点。日志只含组件、来源 ID、匿名状态与聚合计数；不得记录代理 URL、凭据、UUID、私钥、客户端 IP 或测试载荷。

## 部署与验证

`serve` 启动必须提供部署专用的 fingerprint HMAC 密钥文件（Compose 以 Docker secret 挂载到 `/run/secrets/fingerprint_key`）；密钥只存在部署环境，需备份并在测试和生产使用独立值。缺失密钥时服务拒绝启动。测试环境切换和生产部署尚未执行。部署前备份数据库和最后有效发布，直接替换旧 collector 与契约，不做双轨运行或旧状态迁移。异常时恢复工件并修复 FN-2.0。当前可验证不同来源周期、来源失败、长列表轮转、跨来源去重、空发布及恢复；跨批候选状态、分配集中度和反馈误报须待相应实现后验收。定期清理过期数据并检查磁盘/CPU/内存和发布新鲜度。

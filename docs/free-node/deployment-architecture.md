# FN-2.0 部署架构

**目标架构，尚未部署。** 测试阶段使用 Hostinger 马来西亚 KVM1、Cloudflare Tunnel、Go collector、SQLite、Docker Compose 与 systemd；这些基础设施可继续使用，但现有容器仍执行旧逻辑。FN-2.0 将在测试环境直接替换旧实现，collector 与 Android 仍独立构建、测试、部署和回退。VPS 不转发用户代理流量。

```text
公开来源 ──> 来源注册表（各自更新周期） ──> 跨来源候选池（不可逆指纹与状态）
                                             │
                                             ├─ 安全检查与轮转功能探测
                                             ├─ 按质量、分配压力和来源多样性组合清单
                                             └─ 匿名反馈聚合与复测调度
                                                       │
Cloudflare Tunnel ──> 仅本机监听的分发服务 ──> Android 本地节点池与最终选择
```

SQLite 单写入进程保存来源注册表、候选状态、来源关联、探测结果、聚合分配计数和聚合反馈，不保存可还原的节点配置。短暂探测配置只在受限加密工作区存在，当前有效发布与回退工件按 [数据规则](threat-model.md) 保留。密钥只放部署环境，不能进入仓库、镜像、日志或数据库。

来源管理入口不对公网开放。公开入口只提供版本化清单、匿名反馈和健康检查；Cloudflare 负责 HTTPS、边缘限流与基础防护，服务只绑定本机。反馈入口不保存请求 IP、设备标识或用户—节点长期映射。发布与候选状态必须原子提交；失败时继续提供最后有效清单。

调度器按来源到期时间启动有界抓取和全局轮转探测，不并行运行同一批次。独立健康检查报告分发接口、清单新鲜度、来源停用、探测积压、发布失败、CPU、内存和磁盘状态。协议探测进程采用非 root、只读、最小权限、PID/内存/CPU 和短超时限制；禁止通用端口扫描或带宽测试。

测试环境切换前备份数据库与最后有效发布；直接启用 FN-2.0，不做新旧机制并行。异常时恢复可恢复工件并修复 FN-2.0。单机资源持续不足时先量化瓶颈，再增加 CPU；需要多实例或高可用时才引入共享数据库和任务租约。Android CI 不依赖 Go，collector CI 不依赖 Gradle。

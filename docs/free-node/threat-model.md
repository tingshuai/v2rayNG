# FN-2.0 数据保留与威胁模型

**FN-2.0 隐私控制已实现，collector 已部署并完成基础真机验收。** 免费节点由未知运营者控制。启用前警告用户不要通过它们发送凭据、付款信息或其他敏感数据。功能需用户主动开启；匿名质量反馈默认开启，可单独关闭。真机验证了 manifest 导入、后台有限探测和聚合反馈；未通过候选节点承载普通设备流量。

| 风险 | 控制 |
| --- | --- |
| 私网访问与 DNS 重绑定 | 来源和节点均只接收公开地址；DNS 解析后及连接前再次校验。 |
| 恶意或失效节点 | 安全违规立即撤销；普通故障降级、隔离、有限复测；本地真实结果决定选择。 |
| 大量用户拥挤同一节点 | 加权分配、来源重复惩罚、节点级日聚合分配压力与降权；每个候选每天最多分配 500 次。长期集中度仍需生产数据评估。 |
| 长列表节点永远不被测到 | 各来源基本份额、跨批次轮转和新节点探索预算。 |
| 反馈误报与投毒 | 普通网络健康前置检查、入口限流、跨时间复测；单个报告不得全局删除。 |
| 隐私或凭据泄漏 | 无设备 ID、长期用户—节点映射或请求 IP 留存；日志/反馈不含配置和测试载荷。 |

## 数据类别

| 数据 | 位置与用途 | 删除规则 |
| --- | --- | --- |
| 来源最小配置 | VPS 注册表，按各自周期拉取 | 来源删除时移除；当前非秘密审计记录保留 30 天。 |
| 节点指纹、探测结果、聚合分配计数 | VPS SQLite，跨来源去重、探测冷却、分发加权 | 候选长期未见时，只有在超过 30 天且所有关联来源后续成功清单均确认缺席后才过期。反馈只弱化调整分发权重，不延长安全撤销或候选过期。 |
| 匿名反馈聚合 | VPS SQLite，候选 HMAC ID、UTC 日、结果、延迟档和饱和值 | 最多保留 7 天；不保存原始请求、客户端时间或请求地址。权重只采用每种结果最多 5 份的计数并限制在约 ±10%。 |
| 候选安全撤销标记 | VPS SQLite，HMAC 候选 ID 与允许的非秘密原因代码 | 一直保留到显式恢复，防止源再次发布后重新下发；撤销/恢复审计在 30 天后清理。 |
| 可还原候选配置 | 临时探测文件与当前发布工件 | 临时 sing-box 配置在探测结束时删除；有效订阅保留到替换，回退副本最长 7 天。完整配置不写入 SQLite、普通日志或仓库。 |
| 本机节点配置和探测历史 | Android MMKV，现有探测评分、稳定选择和服务端候选 ID 关联 | 关闭功能时清理专用订阅和历史；新清单缺席时本地保留最多 7 天。撤销节点立即退出策略组，但本机 profile 的物理清理尚未实现。 |

分发有最多 3 个可用来源的覆盖目标和每候选每日 500 次上限；这些是候选分配保护，不代表实测用户容量。不得把一次失败或一个来源缺席视作全局删除条件。所有数据只用于该功能。不得上传或记录完整代理 URL、凭据、UUID、私钥、客户端 IP、设备标识、Android 默认 User-Agent、浏览内容或测试载荷；部署文件、数据库和运行输出不得进入仓库。

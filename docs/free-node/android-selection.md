# FN-2.0 Android 状态与选择

**FN-2.0 实施状态：已实现并完成基础真机验收。** 客户端使用 MMKV、受生命周期约束的后台任务、真实探测和 Xray 策略组能力。免费节点功能由用户主动开启；未开启时原有 VPN、仅代理、root 和订阅行为不变。Android 10 专用测试机已从生产 manifest 导入候选并验证后台反馈；连接自动策略组时没有本机成功候选，客户端现在会明确报错并清理失败启动资源，不再生成引用缺失 `balancer-main` 的配置。用户授权对专用机进行真实节点连接验证；截至本次验收，没有节点通过本机验证。

## TalkBack 检查记录（2026-11-18）

旧版页面在 Android 10 / MI 6X 的 Play Store Debug 构建（版本 2.3.15）上检查了 Compose 无障碍节点树。订阅卡片当时只有进入节点页这一项操作；卡片朗读节点统计，节点卡片提供本地化名称、协议、健康状态及 `selected` 状态。订阅卡片内菜单作为独立操作入口。

**阶段结论：本阶段不做 TalkBack 语音验收，该项按产品决定验收关闭，不作为当前交付遗留。** 本机无 TTS 引擎，因此这里只记录无障碍节点树观察，不声称验证了实际语音播报。

## 订阅选择与节点入口（FN-2.1）

订阅卡片主体只选择订阅，并通过选中样式和 `selected` 语义呈现；“节点列表”按钮只切换正在浏览的节点组，保留已选订阅。节点列表选中服务器时，若其所属组就是当前浏览组，则同步该订阅选择。底部连接状态栏和启停按钮仍使用现有服务流程。MI 6X 上的触屏与 D-pad 操作已检查；本次没有启用 TalkBack，因此没有记录新的语音播报结果。

免费节点订阅更新读取 `/manifest`，校验版本、时效、摘要、候选 ID 和配置，再通过现有 profile parser 导入。客户端按连接字段设备本地 HMAC 指纹保存服务端候选 ID 映射；替换前，将最近 7 天内测通、未隔离且未撤销的最多 16 条缺席旧配置并回新订阅。Xray 专用策略组只纳入至少一次本机测通、未隔离且未撤销的 profile；未测新候选与隔离候选通过现有有限 `RealPingWorkerService` 后台抽样探索。该合并使用现有批量 profile 保存操作。服务端撤销项会从策略组和专用订阅的本地 profile 存储中物理删除，并清除对应历史与映射。本地失败历史仅在关闭功能时清除。若自动策略组没有可用成员，启动前返回本地化错误，不创建缺少 balancer 的路由配置。

## 首页与列表交互（FN-2.1 设计）

### 订阅集合与自动选择语义（待确认）

产品语义对齐记录（2026-11-19）：订阅列表中的条目代表一组节点，用户选中某个订阅集合后，直接使用现有底部连接按钮启动该集合。连接时由该集合的自动选择策略挑选质量较好的有效节点；当前节点失效时自动切换到其他较好的节点。自动选择是订阅集合的连接行为，不是“手动导入”订阅中的一个普通节点。对“免费节点候选”而言，这沿用现有“免费节点自动选择”策略，属于首个“免费节点候选”订阅集合。

顶部加号继续提供现有二维码扫描、剪贴板导入和本地导入入口，用于解析单节点或订阅链接（例如用户给出的 Sublink URL）。解析完成后生成订阅名称并作为一个节点集合加入订阅列表，无需用户输入名称。建议初始命名规则为“手动导入”，如名称已占用则依次使用“手动导入 2”“手动导入 3”等；同一批导入解析出的节点归入该集合。订阅条目的可编辑名称仍可沿用现有订阅管理能力。

选中普通订阅集合后点底部连接，应对该集合使用自动节点选择，并在失效时切换。免费节点集合沿用专用 Xray 策略组/balancer；普通订阅集合是否已有同等自动选路与故障切换能力，当前文档不能证明，实施前需从现有策略组和连接生命周期代码核实，必要时补齐。普通订阅的节点更新与检测沿用现有订阅自动更新、订阅偏好中的更新后测速以及现有真实测速能力；当前文档称这些能力已存在，但未明确自动更新默认状态、调度周期及更新后测速对候选探测/自动选路的覆盖范围，实施前需逐项核实并据实记录。

### 执行方案（确认后实施）

1. 核实订阅导入流程及节点分组归属、自动更新设置、更新后测速、真实测速入口和现有策略组/balancer 的失效切换行为；记录不同订阅类型的实际能力与差异。
2. 调整首页订阅集合选择及底部连接映射，使选中集合成为连接目标；移除“免费节点自动选择”作为手动导入普通节点的呈现/耦合，免费候选集合自身提供自动选择。
3. 复用现有二维码、剪贴板、本地文件解析和订阅管理流程；解析结果按自动命名规则成为独立集合，保留用户后续重命名能力。
4. 对普通订阅连接实现集合内质量选择与失效切换，优先复用已有机制；保留免费节点专用策略组、VPN/仅代理/root 模式分支及未启用免费节点时的既有行为。
5. 确认并呈现自动更新和测速状态；仅在核实后决定是否补充设置或行为，避免重复建设已有调度。
6. 增补订阅选择、导入命名、自动更新/测速、质量选择、故障切换及持久状态测试；按改动路径运行相应 JVM 测试、Play Store Debug 单元测试和 Kotlin 编译，若触及服务生命周期则补设备/模拟器验证。

验收：每种订阅集合均可选中并由底部连接按钮启动；连接只使用该集合的节点，按本机真实质量选择，失效后按稳定策略切换；导入后自动生成唯一可读名称并出现在列表中；更新与检测的触发条件/状态有文档和测试依据；免费候选仍是首个默认集合且其现有撤销、安全和有限探测规则保持有效。

当前分支已接入订阅卡片、按真实测速结果计算的统计、最近测速时间记录、节点卡片与订阅详情入口。订阅列表和节点列表的标题使用原顶部标题位；节点页顶部返回订阅列表，搜索图标仅在节点页显示。点击搜索图标后在标题栏输入节点名称或国家/地区进行模糊匹配；输入框提示“搜索节点或国家”，列表不再重复显示搜索框。导入和更多菜单保持原有操作，底部沿用现有连接栏。订阅卡片使用 Material 点击反馈。节点地区使用应用内置 Xray GeoIP 数据离线识别公开 IP 字面量，按识别结果提供国家筛选；域名和无法确认的地址显示“未知地区”，不为识别地区进行 DNS 查询。

首页中间区域改为订阅列表，沿用现有 `MainTopBar` 的菜单、标题、搜索、导入加号和更多菜单，以及现有底部连接栏和悬浮启停按钮的外观与操作。免费节点订阅默认排在首位且不能被用户删除；用户添加的订阅可编辑、删除和手动更新。普通订阅仍沿用现有每订阅自动更新设置，以及订阅偏好中的更新后自动测速选项，不新增后台调度能力。

每个订阅卡片按 GUID 加载节点统计，展示总数、真实测试正常数、失败数和未测试数，并标出最近真实测试时间。未测试不得算作正常。点击卡片主体只选择订阅，不进入节点页；卡片上的“节点列表”入口只打开对应订阅的节点页，不改变选择。两种列表共用现有底部启停按钮和连接状态栏。节点行展示协议、可识别的国家/地区、真实延迟和连通性。连接正常文字和前置状态图标使用主题绿色，失败使用主题错误色，未测试使用中性色；延迟 1–200 ms 为绿色、201–500 ms 为主题强调色、超过 500 ms 为错误色。地区优先取 feed 元数据，缺失时再进行安全的地区识别；无法确认时显示“未知地区”，不得根据名称猜测。国家筛选只对识别成功的地区生效。

底部现有信息区域继续响应“测试当前节点”操作，显示连接目标名称和最近延迟；未连接时悬浮按钮启动所选节点或当前订阅的自动策略，运行时悬浮按钮停止服务。免费节点默认使用专用自动策略组，普通订阅与手动导入节点仍可通过现有选择机制连接。订阅列表和节点列表共用当前启停按钮，不另建连接按钮或并行连接流程。

后台仅测有限候选：近期健康、未测新节点、隔离到期的少量探索样本。当前实现每批最多测 8 条（4 条健康、2 条新候选、2 条隔离恢复），要求有网络且电量不低。连续 3 次失败后隔离 30 分钟；最近 7 天内测通且缺席的配置最多保留 16 条。当前节点保持由现有 Xray 策略组/balancer 管理；本机评分在挑战者连续两轮领先 800 分后更新本地优选记录。服务端撤销候选会立即从策略组排除，并从专用订阅的本地 profile 存储中物理删除；对应的历史记录、候选映射和本地优选记录也会清除。服务端 manifest、质量权重与撤销已接入。**真实代理链路尚未验收**：用户会手动测试；后续自动验收应在测试手机上启动候选代理连接，再打开 Google Chrome 访问普通网页验证实际连通性，并记录结果。只导入订阅或执行节点测速不等于代理链路通过。不得通过免费节点传输凭据、付款资料或其他敏感流量。

匿名质量反馈使用现有有限探测任务与独立的可关闭设置。报告仅在普通非 VPN 网络确认可用后发送；启用前继续展示免费节点不适合凭据、支付等敏感流量的警示。

测试必须覆盖清单更新时旧好节点保留、失败节点退出、冷却后恢复、安全撤销、当前节点稳定、后台取消/约束、反馈开关和网络健康前置条件，以及 VPN、仅代理和 root 受影响路径。

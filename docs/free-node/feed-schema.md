# FN-2.0 分发与反馈契约

**目标版本：FN-2.0；manifest 和匿名反馈端到端已部署并完成基础真机验收。** `/manifest` 返回版本化 JSON，`/subscription` 继续返回标准 Base64 文本供通用客户端导入。collector 与 Android 只通过本文件规定的版本化网络契约共享数据，不共享数据库或内部实现。

## 候选清单请求与响应

客户端 GET `/manifest`，服务端返回 `version=2`、RFC3339 `generated_at`/`expires_at`、`content_sha256`、最多 32 条 `{id, config}` 候选及完整 `revoked` 标识列表。候选 ID 是服务端 HMAC 指纹。摘要按候选顺序计算 UTF-8 字节：每行 `id + TAB + config`，然后一行 `--revoked--`，再按字典序追加撤销 ID 行。客户端拒绝版本、有效期、摘要、ID 或配置校验失败的响应，并保留先前有效状态。服务端按近期质量、分配压力和已代表来源惩罚组合清单；请求不要求账户、持久设备 ID、位置或客户端探测历史。清单只记录节点级聚合分配计数，不记录长期用户—节点关系。候选配置必须经 HTTPS 传输；其敏感字段不得进入日志、分析或错误响应。

服务端通过运维命令按 manifest ID 明确撤销候选；撤销标记一直保留到人工恢复该候选，生命周期审计仅保留 30 天且原因只能使用非秘密枚举。撤销候选立即从两类清单中排除。普通清单缺席不等于撤销。客户端把服务端 ID 绑定到本机连接指纹并排除已撤销节点的策略组准入；缺席的本机近期成功节点仍按本机保留规则处理。清单为空、超时或发布失败时不得把最后有效清单替换为空。版本、摘要和候选标识必须在同一次原子发布中一致。策略组与最终选择仅由客户端管理。

清单只能包含已通过完整安全与功能检查的节点；待测节点不得下发。

## 反馈

功能启用后匿名反馈默认开启，设置中可单独关闭。客户端完成本机探测后，只有存在经过系统验证、非 VPN 的普通网络时，才向 `POST /feedback` 发送最多 8 项 JSON 数组；每项仅含 `candidate_id`、`outcome` (`success`/`failure`) 和粗粒度 `latency_bucket`。失败报告的延迟值固定为 `none`；成功延迟档为 `lt_100`、`100_300`、`300_1000`、`gte_1000`。时间窗由服务端按 UTC 日确定。不得发送完整配置、凭据、UUID、私钥、客户端 IP、设备 ID、Android 默认 User-Agent、浏览数据或测试载荷。客户端使用固定通用 User-Agent；服务端不读取、记录或持久化请求地址，不存原始报告，最多全局每分钟接受 120 批。SQLite 仅保留 7 天候选/UTC 日/结果/延迟档聚合。服务端反馈权重最多使用每种结果最近 5 个报告，并将总影响限制在约 ±10%；单个或多次失败都不能触发全局删除。关闭反馈不影响清单获取与本地选路。

## 失败语义

版本不匹配、摘要不匹配或清单不完整时客户端拒绝应用并保留本机旧有效节点；服务端保留最后有效发布。反馈端点失败不得影响清单和连接。反馈字段、聚合和保留期限已按上述定义实现，仍须在真机验证开启、关闭和网络不可用路径。

# 部署与技术栈

## 当前部署决定

首版采集服务部署在 Hostinger 马来西亚 KVM1；公开订阅主机名为 `freenode.go2base.com`，域名由 Cloudflare 托管。该 VPS 只运行采集、初筛、订阅发布和必要监控，不承载用户代理流量，也不作为任何候选节点的中转。

服务实现位于仓库根目录的 `collector/`，是独立 Go 模块；Android 客户端仅位于 `V2rayNG/`。两者可在同一 Git 仓库演进，但不得共享进程、数据库、内部 API、构建链路或发布回滚流程。客户端只消费本文档定义的版本化标准订阅；collector 的数据库和管理入口均为服务端内部实现。

KVM1 的 1 vCPU、4 GB RAM、50 GB NVMe 和 4 TB 流量足够支持有界的 MVP；CPU 是主要约束。因此首版不用 Kubernetes、Redis、Kafka/RabbitMQ、Elasticsearch 或微服务拆分。

## 推荐技术栈

| 层 | 首版选择 | 原因 |
| --- | --- | --- |
| 操作系统 | 当前受支持的 Ubuntu LTS | 维护周期清晰，Docker 与安全更新生态成熟。 |
| 服务实现 | Go 单体服务（标准库优先，必要时使用轻量 HTTP 路由） | 低内存、单二进制部署、适合严格超时/并发控制和网络解析。 |
| 数据库 | SQLite，WAL 模式，单写入进程 | 单机单副本场景下事务足够、备份简单、避免 PostgreSQL/Redis 的常驻资源开销。 |
| 模式迁移 | 嵌入式 SQL 迁移 | 注册表、审计和候选状态均有版本化升级路径。 |
| 节点协议探测 | 受限的 sing-box 子进程 | 覆盖多种常见协议；探测进程可独立设置超时、内存、CPU、进程数和网络边界。 |
| 公开入口 | `cloudflared` Tunnel，服务仅绑定 `127.0.0.1` | 不开放应用入站端口，Cloudflare 负责 HTTPS、WAF 和边缘限流。 |
| 部署 | Docker Compose，固定镜像摘要，systemd 管理 Compose 生命周期 | 组件少、启动/回滚/备份直接，适合单机。 |
| 监控 | 结构化无秘密日志、健康端点、主机指标和外部可用性检查 | 先满足故障发现与审计，不引入重型可观测平台。 |

## 组件关系

```
公开客户端
    │ HTTPS
Cloudflare 代理与限流
    │ Tunnel（出站连接）
cloudflared ──> collector API / 静态订阅（仅 127.0.0.1）
                         │
                         ├── SQLite：来源注册表、运行状态、短期候选状态、审计
                         ├── DNS/公网地址校验
                         └── 受限 sing-box 探测子进程
```

订阅端点是公开只读的；管理接口不对公网暴露。来源增删、暂停和恢复第一阶段通过 SSH 下的受审计管理命令完成；管理 UI 或 API 是后续需求，不属于 MVP。

## 运行限制与默认预算

- 采集器一次只运行一个批次；来源抓取和探测均使用显式的上下文超时与取消。
- 初始探测并发应保守：HTTP/DNS 拉取不超过 4，协议探测不超过 2；根据 CPU、内存、失败率和完成时间再调整。sing-box 固定到经审阅的稳定镜像摘要，且只由 collector 为单次 HTTP 204 探测短暂启动。
- 每个探测子进程使用只读文件系统、非 root 用户、最小 Linux capabilities、CPU/内存/PID 限额和短超时；禁止访问 Docker socket、宿主机目录和管理密钥。
- UFW 默认拒绝入站；SSH 仅从维护者允许的网络访问，其他应用不监听公网端口。Tunnel 由 VPS 主动连接 Cloudflare。
- SQLite 数据库采用每日加密离机备份，并周期性演练恢复；备份与日志同样不得含完整代理配置或凭据。

## 单仓库构建与 CI 边界

- `V2rayNG/` 继续使用既有 Gradle 工作流；默认 Android CI 不安装 Go，也不构建 `collector/`。
- `collector/` 自带 `go.mod`、Go 单元测试、镜像构建文件和无秘密部署样例；其 CI 只运行格式检查、单元测试、安全检查和镜像构建。
- 运行数据库、订阅输出、临时工作区、部署 `.env` 文件、证书和镜像推送凭据均只存在部署环境，必须被 Git 忽略。服务端可以独立暂停来源、回退订阅或停机，无需 Android 发版。

## Cloudflare 配置原则

`freenode.go2base.com` 仅用于 HTTP/HTTPS 订阅和健康检查，使用 Cloudflare Tunnel 发布。订阅公开可读，但应设置边缘速率限制、WAF 基础规则和合理缓存策略；管理路径使用 Cloudflare Access 或完全不发布。

不要为此服务建立 DNS-only 的 A/AAAA 记录；这会暴露源站 IP 并绕过 Cloudflare 的 HTTP 防护。Cloudflare 代理适用于 HTTP/HTTPS，而不是代理节点本身的 TCP/UDP 流量；本设计也不发布后者。

## 何时升级架构

满足任一条件后，先测量再升级：

- 采集批次频繁超过时限、CPU 长时间饱和，或受限探测并发无法满足刷新目标：升级至少 2 vCPU。
- 需要多实例、高可用、跨节点锁或复杂查询：迁移到托管/独立 PostgreSQL；不要在 SQLite 上强行做多写入副本。
- 需要多个采集节点：引入带租约的任务表或队列，但仍保留每来源限流和全局探测预算。
- 订阅流量超过单 Tunnel/单源站的可接受范围：增加第二台实例与 Tunnel 副本，并重新评估缓存、限流和备份。

任何升级必须保留标准订阅契约、来源审计、秘密最小化和客户端本地决策原则。

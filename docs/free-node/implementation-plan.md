# 免费节点自动筛选：实施路径

## 一句话方案

由独立服务从少量已登记、无需人工审核的公开来源收集并初筛候选节点；Android 客户端在用户自己的网络中只测试有限候选集，并稳定地选择节点。公开节点永远只是候选，不是可信服务。

## 用户视角

1. 用户阅读风险提示后，主动启用免费节点功能。
2. App 像更新普通订阅一样下载候选节点；不改变用户已有订阅。
3. App 在合适的网络与电量条件下，实测少量候选节点是否连通、延迟是否合理。
4. App 优先继续使用健康节点。一次慢或一次失败不会立即切换；连续失败，或另一节点连续明显更好时才切换。
5. 失败节点会暂时冷却；新节点只抽样测试，避免耗电或大量移动数据消耗。

## 服务端职责：收集与初筛

服务端与 Android 工程独立部署和运行。它只读取显式白名单中的公开来源，并执行以下有限检查：

- 解析标准订阅格式并去重；
- DNS 解析后拒绝环回、私网、链路本地和其他非公网目标，并在连接前再次核验解析结果；
- 用短超时、限并发和限重试进行 TCP/TLS 可达性检查；
- 可选地经代理请求一个很小的 HTTP 204 测试页面；
- 发布通过初筛的普通 V2Ray 兼容订阅。

服务端不做端口扫描、不执行带宽测试，也不保存或输出用户数据。服务端测试结果只用作客户端第一次排序的弱参考。

## 客户端职责：实测与选择

客户端是“能否真正使用”的唯一权威。它复用现有订阅更新、真实延迟测试和 Xray 策略组/观测能力，而不另起一个无限制后台探测器。

每轮只选取：近期表现好的少量节点、少量新节点，以及冷却期结束的少量节点。评分优先级为近期真实成功、成功率和稳定性；EWMA 延迟与抖动用于同等稳定节点间的比较。服务端分数不可覆盖本地结果。

自动模式使用专用免费节点策略组。健康的当前节点必须在达到连续失败阈值后才可被替换；挑战者也必须在多次测量中具有有意义的优势。失败节点进入 TTL 隔离，隔离后才可再次抽样。

## 必须避免的做法

- 不在 App 内置任意第三方节点清单或抓取规则。
- 不直接相信第三方“测速可用”结论。
- 不对全量节点无限制测速，也不在移动网络上进行带宽测试。
- 不因一次失败删除节点或频繁切换当前节点。
- 不让外部订阅下发并控制本功能的策略组；策略组由客户端创建和管理。
- 不将完整代理链接、凭据、用户 IP 或访问内容写入日志或上传。

## 分期交付

1. 先完成版本化普通订阅输出、来源白名单和服务端安全初筛。
2. 客户端增加明确的启用/风险同意流程，导入专用订阅和本地安全指纹。
3. 加入有限探测、历史评分、失败隔离与滞回决策，并以专用策略组运行。
4. 补齐迁移和决策单元测试；涉及 VPN、核心、后台或生命周期时做真机/模拟器验证。

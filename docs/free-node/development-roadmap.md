# FN-2.0 开发节奏与验收

**目标版本：FN-2.0；主要实现已部署，基础验收通过。** 本路线直接替换测试阶段的旧机制。2026-11-11 的 P0–P4 记录保存在 [历史试运行记录](p4-end-to-end-trial.md)，不代表 FN-2.0 验收。Collector 的轮转、有界探测、候选来源关联/过期、来源多样性、日分配上限、manifest、撤销与匿名反馈已实现并部署；Android manifest 导入、撤销隔离、反馈开关与聚合上报已接入。手机从生产 manifest 导入 21 条候选，后台探测成功运行，生产端收到 2 条聚合报告。未将免费节点用于设备普通流量；真实代理连接与长期分配集中度仍需持续观测。免费节点功能由用户主动启用；匿名质量反馈默认开启，可单独关闭。未启用用户维持原有 v2rayNG 行为。

本阶段不安排 TalkBack 语音验收，该项按产品决定关闭。真实代理链路由用户手动验收；后续自动验收如运行于专用测试手机，应优先连接候选后打开 Google Chrome 访问普通网页，并记录连接和访问结果。

1. **契约和数据规则**：固定来源周期、跨来源指纹、候选状态、过期/删除、分发、反馈以及保留期。交付无秘密夹具和数据库迁移设计。验收：每项数据有用途、位置和删除规则。
2. **VPS 候选池**：已实现并通过 Go 测试：来源失败保护、跨批轮转、每批最多 50 次有界探测、跨来源去重、来源关联、全关联来源成功确认缺席后 30 天过期、失败冷却与隔离。
3. **质量分发**：已实现并通过 Go 测试：每次最多 32 条、至少覆盖最多 3 个可用来源、500 次/候选/日硬上限、节点级分配计数与来源重复惩罚。长期分配集中度需生产数据继续评估。
4. **Android 本地池与选择**：已接入 manifest 校验、服务端候选 ID 到本地指纹映射、近期成功节点保留、撤销隔离和有界后台探测。真机完成生产清单导入及后台任务运行；未通过未信任候选节点承载普通设备流量。
5. **默认反馈**：已实现并在真机触发。设置重启后保持默认开启；反馈只包含匿名 HMAC 候选 ID、成功/失败和延迟档，生产端仅新增 UTC 日聚合，未创建原始报告记录。Go 测试覆盖输入校验、限流和弱权重。
6. **直接替换与部署**：已备份生产数据库卷、发布文件和运行单元，仅替换 FreeV2ray collector；更新定时 runner 并通过健康、manifest 和 Android 导入验收。原镜像及备份可用于回滚。

必须记录每天探测的不同节点数、重复探测率、来源覆盖、用户找到可用节点的比例与时间、分配集中度及资源消耗。Android 和 collector 各自独立构建、测试和运行；文档、契约和测试夹具随实现更新。

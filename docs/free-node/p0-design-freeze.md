# FN-2.0 设计决定

**本文件是 FN-2.0 的目标决策，尚未实现。** 旧 P0 的冻结与验收结论只属于测试阶段的旧方案，见 [历史试运行记录](p4-end-to-end-trial.md)。

- 公开且无需认证的 HTTPS 来源由服务端注册表管理，各自保持独立更新周期。来源成功更新才改变其节点关联；抓取失败不代表旧节点消失。连续抓取/解析失败可暂停来源，恢复需显式操作。
- 候选按连接相关字段规范化，使用密钥 HMAC 指纹跨来源去重。候选状态为待测、可下发、降级、隔离、过期；保留出现时间、检查结果、下次复测与来源关联。可还原配置不写入长期数据库。
- 格式或地址安全违规立即停发。普通失败先降级，再经跨时间重复失败隔离与复测。因来源消失而删除，必须在所有关联来源成功更新中持续缺席且超过保留期。删除配置后暂留失败指纹防止重复筛选。
- 全局探测预算分配给未测、到期健康及隔离到期的节点；各来源有基本份额，长列表的进度跨批次轮转。DNS 解析后和连接前均校验公网地址，禁止通用端口扫描和带宽测试。
- 分发根据近期成功、稳定性、新鲜度、分配压力和容量上限加权，同时约束来源多样性与新节点机会。手机上的真实测试是最终选择依据；健康当前节点不因单次结果切换。
- 免费节点功能仍由用户主动开启。启用后匿名质量反馈默认开启，可单独关闭。服务端只接收匿名候选标识和粗粒度结果；单个反馈不能全局删除节点。
- 新方案在测试环境直接替换旧逻辑，不做旧协议或旧状态迁移。详细契约、保留期和实施验收分别见 [分发契约](feed-schema.md)、[数据规则](threat-model.md)、[开发节奏](development-roadmap.md)。

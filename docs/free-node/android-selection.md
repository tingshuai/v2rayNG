**FN-2.0 实施状态：已实现并完成基础真机验收。** 客户端使用 MMKV、受生命周期约束的后台任务、真实探测和 Xray 策略组能力。免费节点功能由用户主动开启；未开启时原有 VPN、仅代理、root 和订阅行为不变。Android 10 专用测试机已从生产 manifest 导入候选并验证后台反馈；连接自动策略组时没有本机成功候选，客户端现在会明确报错并清理失败启动资源，不再生成引用缺失 `balancer-main` 的配置。用户授权对专用机进行真实节点连接验证；截至本次验收，没有节点通过本机验证。

订阅卡片主体只选择订阅，并通过选中样式和 `selected` 语义呈现；“节点列表”按钮只切换正在浏览的节点组，保留已选订阅。节点列表选中服务器时，若其所属组就是当前浏览组，则同步该订阅选择。底部连接状态栏和启停按钮仍使用现有服务流程。MI 6X 上的触屏与 D-pad 操作已检查；本次没有启用 TalkBack，因此没有记录新的语音播报结果。

## 首页与列表交互（FN-2.1 设计）

### 当前连接栏与检查交互（2026-11-20）

首页底部横条表示当前选中的连接目标（订阅集合或手动节点），展示该目标名称及其最近一次真实连通性检查状态。横条整行均为检查当前目标的点击区域；检查请求只在连接服务运行、目标有效时发起。点击横条重复检查当前目标，不负责启停服务。右侧悬浮方块按钮只负责连接开关：未运行时启动当前选中的订阅/节点，运行时停止连接。

测试状态与连接是否正在运行分开表达。新目标被选中时立即清除前一目标的延迟/结果，并进入待检查状态；切换必须实际把活动配置指向新订阅策略组或节点，并重启运行中的服务（未运行时通过现有权限流程启动）。服务成功启动后立即对新目标执行一次现有真实连通性检查，不能依赖固定延时发送请求。检查进行中底部方块使用中性灰色；当前目标检查成功为绿色，失败为红色；尚无当前目标结果时为灰色。失败结果必须保留为失败状态，不能被服务仍在运行这一事实覆盖。结果只属于发起检查时的当前目标，旧请求或旧目标的延迟数据不得改变新目标的底栏状态。

此交互复用现有 Android `MainViewModel` 的服务状态、`TestCurrentServer` 动作、真实 ping 请求和 `MainActivity` 的启动/重启流程；不新增并行连接服务或另一套探测调度。订阅自动选择模式显示订阅集合及自动标记，不把 Xray balancer 的最近测速候选冒充为当前活动节点。

### 测速列表与连接状态栏（FN-2.3 实施）

节点页摘要行以统一紧凑高度显示节点总数、已测数、通过数和失败数；这些计数直接来自当前列表状态，测速结果到达后实时更新。空闲时右侧按钮标为“节点测试”并配速度表图标，运行时显示加载图标、“正在测试”和按完成数计算的百分比，不展示内部计数比；运行与空闲时摘要行保持同一高度。国家筛选和摘要行固定，节点卡片列表独立滚动。订阅卡片的“节点列表”入口使用较大的右向箭头。批量真实测速每收到结果就把通过节点稳定地排到未测试/失败节点之前；批次完成后按持久测试延迟写回该订阅顺序，重进页面仍保持通过节点优先。节点卡片的失败状态只显示在节点测试状态位置，延迟位置只显示成功的毫秒值。

底部状态栏明确标注“订阅自动”或“手动节点”，标题显示选择的订阅名或手动选择的节点名。底部横条负责触发当前目标的真实检查并展示检查状态；右侧连接开关的颜色只表达当前目标检查状态，不得仅因服务正在运行而变绿。横条整行均可点击。当前 Xray balancer 活动成员没有从现有客户端 API 暴露给 UI，因此自动模式下状态栏只能显示订阅名和该订阅目标的检查状态，不能准确标出 Xray 此刻正在转发的具体节点；不可用最近测速最优节点冒充当前活动节点。

### 订阅集合与自动选择语义（FN-2.2）

产品语义对齐记录（2026-11-19）：订阅列表中的条目代表一组节点，用户选中某个订阅集合后，直接使用现有底部连接按钮启动该集合。连接时由该集合的自动选择策略挑选质量较好的有效节点；当前节点失效时自动切换到其他较好的节点。自动选择是订阅集合的连接行为，不是“手动导入”订阅中的一个普通节点。对“免费节点候选”而言，这沿用现有“免费节点自动选择”策略，属于首个“免费节点候选”订阅集合。

顶部加号继续提供现有二维码扫描、剪贴板导入和本地导入入口，用于解析单节点或订阅链接（例如用户给出的 Sublink URL）。解析完成后生成订阅名称并作为一个节点集合加入订阅列表，无需用户输入名称。初始命名规则为“手动导入”，如名称已占用则依次使用“手动导入 2”“手动导入 3”等；URL fragment 提供非空名称时优先使用该名称并按相同规则去重。同一批导入解析出的节点归入该集合。订阅条目的可编辑名称仍可沿用现有订阅管理能力。

选中普通订阅集合后点底部连接，对该集合使用自动节点选择，并在失效时切换。免费节点集合沿用专用 Xray 策略组/balancer；普通订阅集合复用一个内部策略组 profile，选择订阅时把该 profile 指向目标订阅，再由 Xray 的 least-ping observatory/balancer 选择成员。内部 profile 存在 MMKV 的设置数据中，不混入“手动导入”或订阅的节点列表。启动器只在选择目标是缺失/错配的策略组时补齐映射，保留直接节点和 Tasker 明确传入的 profile。普通订阅没有匹配的手动策略组时使用该内部 profile。

“免费节点自动选择”是免费订阅使用的内部策略组 profile，不再作为“手动导入”里的节点展示。UI 从服务器列表中过滤内部自动选择 profile；底层 profile 仍保留给第一个免费订阅作为连接入口，关闭免费节点时仍按原流程清除。

### 订阅/节点切换诊断日志（2026-11-20）

首页选择订阅或节点、目标订阅能否解析到策略组 profile、重启请求及 daemon 确认、核心配置启动、策略组过滤后的成员集合、真实连通性检查均写入 `FN_DIAG` 信息级 Android logcat 记录。记录用 profile/group 标识的 SHA-256 短摘要关联流程；成员列表同时记录短摘要的 profile 标识、服务器地址和地址+端口，便于比较不同订阅是否含有同一配置端点。连接检查保留其实际代理出口 IP、国家、延迟，并记录是否与策略组中某成员的服务器 IP 完全相同。

诊断记录只写入 Android logcat 的有界环形缓冲区，由系统持续覆盖旧记录，不在应用私有存储中追加日志文件，因此不会随运行时间增长占满磁盘。通过 `adb logcat -s com.v2ray.ang:I` 查看。日志不包含原始 GUID、订阅 ID、完整代理配置或认证字段。策略组成员日志仅保留最多 64 项，出口 IP 与成员服务器地址仅在完全相等时关联；域名解析、NAT、CDN 或 Xray balancer 的实际活动成员可能使出口 IP 与配置服务器不同。当前客户端 API 不提供 Xray 实时转发成员，因此日志可确认“哪个集合被选中、哪些成员写入了 balancer、服务是否按新选择重启、真实代理出口是什么”，但不能在出口不等于节点服务器地址时声称识别了当前活动成员。

在 MI 6X（Android 10，Play Store Debug 2.3.15）上，2026-11-20 真机复核确认了旧根因：从“免费节点候选”切到 `import sub` 或“手动导入”时，旧逻辑找不到目标 `POLICYGROUP` profile；daemon 重启原免费订阅 profile，出口没有变化。普通订阅缺少自动策略组 profile，`ensurePolicyGroupSelection` 找不到组后提前返回。修复后选择 `import sub` 会记录目标 profile 与目标订阅一致、Xray 核心按该目标启动；UI 也能显示当前订阅的连接检查结果。普通策略组只纳入本机已测成功的成员，避免一个未验证且解析无效的配置令整个 Xray 核心启动失败。此机上该订阅有 64 个节点，其中 27 个真实测试成功、37 个失败，成功成员被用于策略组；底部连接检查显示 395 ms、出口 `80.174.118.151`（意大利）。这个出口 IP 与组内成员配置服务器地址不一致，因此不能仅凭出口 IP 反推出本次请求命中了哪台节点。

### 核实结果与实施记录

- 普通订阅周期更新已存在：每订阅 `autoUpdate` 开关，默认 24 小时间隔；启用后由 `SubscriptionUpdater` 以联网约束的周期 WorkManager 任务更新，最小间隔遵循代码常量。启动或设备启动时会同步订阅周期任务；订阅级自动更新默认关闭，订阅编辑可启用并设为 24 小时间隔（默认值），最小 15 分钟。手动更新入口始终可用。
- 更新后测速已存在：订阅管理偏好中的全局开关默认关闭；开启后由 `SubscriptionUpdateService` 测速更新节点。免费节点候选另有 `RealPingWorkerService` 有界抽样，周期更新 feed 与后台抽样互相独立。
- 普通订阅连接前没有按集合自动选择：底部启动原来直接使用当前选中 GUID。策略组/balancer 已能按 Xray observatory 选择及排除探测失败的候选；本次改为订阅选择时活动配置指向该集合的策略组，并为免费节点策略组明确采用 least-ping 探测策略。自动切换依赖 Xray 运行时探测，不是客户端按单次本地测速反复改选。
- 二维码/剪贴板/本地导入本来会解析标准订阅 URL；新订阅无 fragment 名时生成“手动导入”，重名追加序号；URL fragment 若有值则用其作为初始名称并执行同样去重。原有订阅管理仍支持重命名。

后台仅测有限候选：近期健康、未测新节点、隔离到期的少量探索样本。当前实现每批最多测 8 条（4 条健康、2 条新候选、2 条隔离恢复），要求有网络且电量不低。连续 3 次失败后隔离 30 分钟；最近 7 天内测通且缺席的配置最多保留 16 条。当前节点保持由现有 Xray 策略组/balancer 管理；本机评分在挑战者连续两轮领先 800 分后更新本地优选记录。服务端撤销候选会立即从策略组排除，并从专用订阅的本地 profile 存储中物理删除；对应的历史记录、候选映射和本地优选记录也会清除。服务端 manifest、质量权重与撤销已接入。**真实代理链路尚未验收**：用户会手动测试；后续自动验收应在测试手机上启动候选代理连接，再打开 Google Chrome 访问普通网页验证实际连通性，并记录结果。只导入订阅或执行节点测速不等于代理链路通过。不得通过免费节点传输凭据、付款资料或其他敏感流量。

匿名质量反馈使用现有有限探测任务与独立的可关闭设置。报告仅在普通非 VPN 网络确认可用后发送；启用前继续展示免费节点不适合凭据、支付等敏感流量的警示。

测试必须覆盖清单更新时旧好节点保留、失败节点退出、冷却后恢复、安全撤销、当前节点稳定、后台取消/约束、反馈开关和网络健康前置条件，以及 VPN、仅代理和 root 受影响路径。

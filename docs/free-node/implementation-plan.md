# FreeNode FN-2.0：实施方案

**版本 `FN-2.0`；状态：实施中，尚未完成验收。** 本版直接替换测试阶段的旧逻辑；旧 P0–P4 验收只证明当时的实现，不构成 FN-2.0 验收。Collector 长列表轮转与探测冷却、Android 最近成功节点保留和策略组隔离门槛、标准订阅质量加权分发已有部分实现；跨来源候选池、来源关联/过期、来源多样性、版本化 manifest、安全撤销和反馈仍待实现。免费节点功能仍由用户主动开启；启用后匿名质量反馈默认开启，可单独关闭。

## 用户体验

VPS 汇集不同周期更新的公开来源，维护大候选池，轮流检查节点，并按质量与分配压力为每次请求组合候选清单。手机只测试少量节点，保留本机已验证好用的旧节点。当前节点健康时保持连接；持续失效或挑战者持续明显更好时才切换。启用前继续警告用户：免费节点不可信，不要传输凭据、付款资料或其他敏感数据。

## 来源和候选池

每个来源按注册表中的独立周期获取。只有成功获取才更新其节点清单；获取失败不表示旧节点消失。解析后规范化连接相关字段，计算带服务端密钥的不可逆指纹，跨来源去重，并记录每个节点关联的来源、最近出现与测试时间、结果、下次复测时间和状态。数据库不保存可还原的节点配置。

状态为待测、可下发、降级、隔离、过期。格式错误、非公网地址等安全违规立即停发。普通连接失败先降级，跨时间重复失败后隔离并安排复测。仅在长期失败或长期未见时删除可还原配置；删除后暂留不可逆失败指纹，防止重复筛选。因来源消失而过期，要求**所有关联来源**成功更新后持续缺席，且超过保留期限；单个来源缺席或抓取失败不触发删除。近期有可信客户端成功反馈时可延后普通失效删除，安全违规仍立即停发。

## 轮转筛选

先做格式、去重和地址安全检查，再对候选做 TCP 与小型代理功能检查。DNS 解析后及每次连接前都要校验公网地址；不做端口扫描或带宽测试。全局探测预算分给未测节点、到期的健康节点、隔离期结束的节点；各来源保留基本份额，并记住上次筛选位置。相同指纹跨来源只探测一次；近期已测和冷却中的失败节点不重测。并发和批次预算根据 VPS 的 CPU、内存、完成时间调整。

## 分发与本地选择

VPS 根据近期成功、稳定性、结果新鲜度、近期分配压力和保守的容量上限为节点设置分发权重。每次请求按权重组合清单，同时保证来源多样性和少量新节点探索。好节点获得更多机会，但不能被无限集中分配；表现变差时降权，恢复后逐步升权。服务端只记录节点级聚合分配计数，不维护长期的用户与节点对应关系。清单失败可在次数和流量预算内换一份。任何空结果、超时或发布失败不得清空最后有效清单及回退副本。

手机把新清单与本机仍在保留期、近期验证有效的旧节点合并，按连接字段指纹继承历史。反复失败的节点退出本机可选集合，但暂留失败指纹，避免下一次更新立刻重新加入。旧节点在本机复测失败、超过保留期或服务端明确安全撤销时删除。当前节点健康时不因新清单而切换；后台只探测有限样本并遵守网络、电量和 Android 后台限制。服务端分数只是首次探索参考，最终由本地真实测试决定。

“新节点探索”仅指刚通过完整安全与功能检查的节点；待测节点不得下发。

## 默认开启的匿名反馈

功能启用后，简要质量反馈默认开启，可单独关闭。手机先确认普通网络正常，再发送服务端发放的匿名候选标识、粗粒度结果与延迟档位、时间窗。不得上传完整配置、凭据、UUID、私钥、客户端 IP、设备标识或测试载荷。入口限流，服务端不保存请求 IP；原始报告短期聚合后删除。反馈用于调权和安排复测；单个用户或单次失败不能全局删除节点。关闭反馈不影响领取清单、探测或选路。

## 交付与验收

1. 固定 FN-2.0 的数据契约、保留期、失败与过期规则，建立无秘密夹具。**进行中**：契约文档和确定性夹具已存在；manifest 字段、候选状态阈值仍待实现。
2. 直接替换 collector 的跨来源候选池、轮转探测、删除与清理逻辑。**部分完成**：筛选游标跨批次持久化，每批共享 50 次并按来源均分的探测预算；HMAC 指纹按 30 分钟失败冷却、三次失败隔离和六小时健康复测。来源关联、质量状态分发及来源缺席过期清理未完成。
3. 直接替换分发逻辑，验证质量权重、来源多样性、分配压力和新节点机会。**部分完成**：现有标准订阅接口按本机探测成功率/新鲜度与聚合分配压力随机抽取最多 32 条，未测节点保留弱探索机会；来源多样性硬约束、容量上限和分发集中度验收未完成。
4. 替换 Android 的清单接收、本地有效节点保留、失败退出与稳定选择。**部分完成**：已有本机指纹、有限探测、评分和滞回基础；manifest 接收、合并保留及安全撤销未完成。
5. 接入默认开启、可关闭的匿名反馈，并验证误报防护与最小数据边界。**未完成**。
6. 在测试环境直接启用 FN-2.0，不做新旧逻辑并行或旧数据兼容。**未完成**：尚未切换测试环境或部署。

验收指标包括：每天完整测试的**不同**节点数、重复测试率、来源覆盖、用户找到可用节点的比例和耗时、分配集中度、VPS 资源与手机耗电/流量。每个确定性规则须有测试；后台、核心与服务生命周期变更须做设备或模拟器检查。具体初始预算和保留天数在实施前依据 VPS 测量定值，同步到 [运行手册](collector-runbook.md) 和 [数据规则](threat-model.md)。

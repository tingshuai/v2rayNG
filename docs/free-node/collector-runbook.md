# 采集服务运行手册

## 运行边界

采集器实现位于本仓库的 `collector/`，但在运行、权限、构建、发布和回滚上独立于 `V2rayNG/`。它只访问显式配置、公开且无需认证的来源；当前阶段的来源准入仅按技术可用性判断，不因授权或再分发许可阻断接入。不保存 VPS 凭据、来源账户 Cookie、生产节点清单或完整代理配置到本仓库。来源不要求人工审核或负责人信息；不得接入要求登录、Cookie、验证码、认证令牌或绕过访问控制的来源。

采集服务应使用自己的数据库维护来源注册表和运行状态。这是来源增删、暂停、审计和按来源限流的唯一操作入口；Android 客户端不维护来源清单。数据库不是永久节点仓库：只保存实现去重、短期复测和安全审计所需的最小候选状态，并按保留期清理。

每个来源至少维护稳定来源 ID、获取地址、启用状态、格式/契约版本、允许的获取频率、最近成功/失败时间、连续失败计数和暂停原因。不得记录负责人或用途说明。含认证材料的地址不符合准入条件，必须拒绝，不能写入数据库明文、日志、客户端或本仓库。

## 每次运行

1. 拉取已启用来源，并遵守每来源的频率限制。
   新增、修改、启用、暂停或删除来源必须通过来源注册表完成，保留时间、动作、原因和变更前后的非秘密字段审计记录。
2. 解析、规范化和去重候选配置。
3. 解析每个目标的 DNS；拒绝非公网地址。连接前重新解析并核验，以防 DNS 重绑定。
4. 在严格的并发、短超时和有限重试条件下做语法、TCP/TLS 和可选 HTTP 204 检查。
5. 发布普通订阅；失败和超时不应阻断上一次有效输出的可用性。

单个来源最多读取 2 MiB、解析 5,000 条候选；解析完成后仍只从支持完整探测的协议中选择最多 50 条进入 TCP 与代理检查。超额输入会被拒绝，不会扩大探测或发布预算。

对按日发布且路径规律固定的公开订阅，可在路径中使用唯一的 `{YYYYMMDD}` 占位符；采集器会以 UTC 日期替换它。该机制不会解析来源网页、不会跟随重定向，也不接受其他模板表达式。

每个批次开始时会删除超过 7 天的回退订阅副本；当前有效订阅不会被保留清理删除。新一次成功发布替换当前有效订阅时，前一份有效订阅作为新的回退副本重新计时。

VLESS（TCP、WebSocket、gRPC、TLS、Reality）、Trojan 与 Shadowsocks 候选会在 TCP 初筛后交给固定版本的 sing-box 子进程执行小型 HTTPS HTTP 204 探测。Reality 必须含公钥；每次探测只创建一个 `0600` 的临时配置，结束即删除；配置使用重新解析后的公网 IP 连接，并保留原主机名仅作 TLS SNI。子进程在只读、非 root、无 Linux capabilities、PID 与内存受限的容器内运行。其他协议或传输在探测阶段拒绝，不作猜测性转换。

每轮仅记录来源级聚合计数：不支持、TCP 失败、代理 HTTP 失败、非 204 状态、无效候选和通过数。日志不得包含候选地址、配置、凭据、UUID、私钥或单条错误内容。

## 事故处理

- 来源返回异常内容、非预期重定向或疑似恶意配置时，立即禁用该来源并保留不含凭据的审计摘要。
- 检查发现私网、环回、链路本地或保留地址时，拒绝候选并记录来源标识与拒绝原因，不能记录完整代理链接。
- 输出异常膨胀、超时或资源消耗异常时，停止该轮并维持最后一次成功发布，调查后再恢复。

来源连续三次拉取失败也必须自动暂停。恢复暂停来源只能经显式启用操作；恢复后的首轮必须重新执行全部安全校验与预算限制，不能由定时任务自动恢复。

采集器不是通用端口扫描器；禁止扩大端口范围、进行高流量下载测试或绕过来源限流。
